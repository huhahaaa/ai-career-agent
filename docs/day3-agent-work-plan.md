# Day3 Agent 面试能力优化任务书

## 目标

今天 Agent 组员的核心任务是让模拟面试更像真实面试官，而不是只做普通问答。重点是增强答非所问识别、逐题评分结构、报告生成和训练计划质量。

建议主题：

> 优化面试 Agent 的追问、评分、报告和训练计划，让模拟面试更适合答辩展示。

## 当前 Agent 现状

目前模拟面试已经具备：

- 多轮提问
- DeepSeek API 接入
- 不同面试模式基础支持
- 逐题反馈
- 总分
- STAR 改写建议
- 下一轮训练计划
- 面试历史记录
- 报告页展示

当前仍需继续优化：

- 对答非所问的处理不够强。
- 评分反馈还可以更结构化。
- Prompt 需要减少 Markdown 符号和不稳定格式。
- 面试模式之间差异还可以更明显。
- 报告内容需要更适合最终展示。
- 低质量回答、过短回答、空泛回答的测试用例还需要补充。

## 今日建议任务

### 1. 强化答非所问识别

目标：用户回答没有回应问题核心时，Agent 不应该正常推进，而是提醒用户补充。

建议逻辑：

```text
问题要求：描述注册登录和 Token 鉴权方案
用户回答：我觉得这个项目很有意义，页面也很好看

Agent 应提示：
你的回答没有回应问题核心。请补充：
1. 注册时如何保存用户
2. 密码如何加密
3. 登录后如何生成 Token
4. 后端如何校验 Token
```

可以在评分前增加问题相关性判断：

```python
relevance_result = judge_answer_relevance(question, answer)
```

返回结构建议：

```json
{
  "is_relevant": false,
  "missing_points": ["注册流程", "密码哈希", "JWT生成", "Token校验"],
  "follow_up_hint": "请围绕注册、登录、JWT鉴权流程补充回答。"
}
```

处理规则：

- 如果明显答非所问：内容相关度降分。
- 如果只回答了一部分：生成针对性追问。
- 如果回答过短：提示用 STAR 或技术流程展开。

### 2. 优化逐题评分结构

目标：让每一题的反馈都稳定包含用户能理解的内容。

建议每题反馈结构：

```json
{
  "score": 78,
  "summary": "回答覆盖了主要流程，但缺少安全细节。",
  "strengths": ["说明了 JWT 鉴权流程", "提到了密码哈希"],
  "issues": ["没有说明 Token 过期处理", "没有提到刷新机制"],
  "suggestions": ["补充过期时间、刷新策略和异常处理流程"],
  "follow_up_question": "如果 Token 过期，前后端分别应该如何处理？"
}
```

前端展示时可以直接使用这些字段。

### 3. 面试模式差异化

目标：四种模式不是只换名称，而是提问风格和评分重点不同。

建议模式：

```text
HR 面
技术面
压力面
反馈教练
```

差异建议：

- HR 面：关注表达、经历、动机、团队协作。
- 技术面：关注方案细节、技术选型、边界情况、性能安全。
- 压力面：关注追问、质疑、取舍、风险解释。
- 反馈教练：重点给修改建议，不刻意施压。

示例：

```text
技术面追问：
你刚才提到了 JWT，请说明 Token 过期和刷新机制如何设计。

压力面追问：
你说这个方案很安全，但如果 Token 被盗用怎么办？

反馈教练：
你可以把回答改成“背景-方案-安全措施-验证结果”的结构。
```

### 4. 优化 Prompt 输出格式

目标：减少 Markdown 符号，让前端展示更稳定。

Prompt 中建议明确要求：

```text
不要输出 Markdown 标题、列表符号、表格。
不要使用 **、###、- 等 Markdown 符号。
请返回严格 JSON。
字段必须包含 score、summary、strengths、issues、suggestions、follow_up_question。
```

如果模型返回不稳定，需要保留规则兜底：

- JSON 解析失败时使用规则评分。
- 缺字段时填默认值。
- 分数超出范围时裁剪到 0-100。

### 5. 完善最终面试报告

目标：报告更像最终成果，而不是普通聊天记录。

报告建议包含：

- 总分
- 分维度得分
- 每题得分
- 每题问题与回答摘要
- 优点总结
- 问题总结
- STAR 改写建议
- 下一轮训练计划
- 答非所问 / 空泛表达 / 绝对化表达提醒

报告结构建议：

```json
{
  "overall_score": 82,
  "dimension_averages": {
    "content_relevance": 20,
    "professional_accuracy": 21,
    "clarity": 16,
    "star_completeness": 15,
    "position_match": 8
  },
  "details": [],
  "star_suggestions": [],
  "practice_plan": "..."
}
```

### 6. 增加低质量回答测试用例

目标：证明 Agent 不是随便打分，而是能识别回答质量。

建议测试案例：

```text
回答过短：
“用 JWT。”

答非所问：
问题问 Token 鉴权，回答项目 UI 设计。

空泛表达：
“我做了很多优化，效果非常好。”

绝对化表达：
“这个方案一定不会有问题。”

缺少 STAR：
只说做了什么，不说背景、行动、结果。
```

预期结果：

- 回答过短被追问。
- 答非所问被提示补充问题核心。
- 空泛表达被要求量化。
- 绝对化表达被提醒改成可验证事实。
- STAR 不完整时给结构化改写建议。

## 最低完成线

如果今天时间不够，最低完成这三项：

1. 答非所问识别和提示。
2. 每题反馈稳定返回得分、优点、问题、建议。
3. 面试报告包含逐题得分和训练计划。

这三项最能提升模拟面试的真实感，也最适合 Agent 组员展示贡献。

## 验收方式

### 场景一：正常技术回答

问题：

```text
你是如何设计注册登录和 Token 鉴权方案的？
```

用户回答包含：

```text
注册、密码哈希、JWT 生成、Token 校验、过期时间、安全处理
```

期望：

- 得分中等偏高。
- 优点能指出技术流程完整。
- 建议能补充刷新机制、异常处理等细节。

### 场景二：答非所问

问题：

```text
你是如何设计岗位匹配算法的？
```

用户回答：

```text
我觉得这个项目界面比较清楚，用户可以点击按钮操作。
```

期望：

- 内容相关度明显降分。
- Agent 提醒没有回答算法核心。
- 追问要求补充语义匹配、技能覆盖、方向降权等内容。

### 场景三：回答过短

用户回答：

```text
用 Redis 做缓存。
```

期望：

- Agent 不直接高分。
- 提醒回答过短。
- 要求补充缓存对象、过期策略、失效策略、性能收益。

### 场景四：压力面

用户说：

```text
这个方案一定不会出问题。
```

期望：

- Agent 识别绝对化表达。
- 追问风险场景。
- 建议改成可验证、可量化的表达。

## 结论

Agent 组员今天最有价值的工作，是让系统从“能聊天”升级到“像面试官一样判断回答质量”。

最推荐优先做：

1. 答非所问识别
2. 逐题结构化反馈
3. 多面试模式差异化
4. 最终报告强化
5. 低质量回答测试
