# Day3 前端体验优化任务书

## 目标

今天前端组员的核心任务是把已经能跑通的功能整理成更自然的用户流程，减少“功能堆叠感”，让普通学生用户知道下一步该做什么，也让答辩展示更顺。

建议主题：

> 打通用户主流程，优化岗位审核、岗位匹配、多岗对比、看板说明和报告导出体验。

## 当前前端现状

目前项目已经具备这些页面：

- 数据看板
- 简历管理
- 简历审核
- 岗位管理
- 岗位审核
- 岗位匹配
- 多岗对比
- 模拟面试
- 面试记录
- 训练计划

已经完成的基础优化：

- 学生账号和审核员账号入口已区分。
- 学生账号隐藏岗位审核入口。
- 匹配结果已显示岗位方向识别和分数解释。
- 面试报告和训练计划已有更完整的展示结构。

当前仍需继续优化：

- 首页缺少清晰流程引导。
- 岗位审核仍偏机械，批量审核体验不足。
- 岗位匹配到多岗对比的流程不够自然。
- 看板数字统计范围需要更明确。
- 薪资图表需要说明统计口径。
- 报告最好提供 Markdown 导出入口，方便答辩展示。

## 今日建议任务

### 1. 首页增加流程引导卡片

目标：让用户进入系统后知道下一步该做什么。

建议在数据看板首页增加流程卡片：

```text
上传简历 → 审核简历 → 匹配岗位 → 多岗对比 → 模拟面试 → 查看报告 → 训练计划
```

每一步建议展示：

- 当前状态
- 下一步按钮
- 简短说明

示例：

```text
1. 上传主简历
   当前主简历：已设置 / 未设置
   按钮：去上传

2. 匹配岗位
   使用当前主简历查找合适岗位
   按钮：开始匹配
```


### 2. 岗位匹配到多岗对比流程打通

目标：让用户自然地从匹配结果进入多岗对比。

推荐流程：

```text
岗位匹配 → 勾选 2-5 个岗位 → 加入对比 → 查看多岗对比
```

岗位匹配结果卡片中建议增加：

- 复选框
- “加入对比”按钮
- 已加入状态

页面顶部或底部增加：

```text
已选择 3 个岗位用于对比
[查看对比]
```

跳转到多岗对比页时，应带上已选择的岗位 ID。


### 3. 薪资图表说明优化

目标：避免月薪、日薪、未公开薪资混在一起造成误解。

多岗对比页薪资区域建议增加说明：

```text
薪资图表仅统计月薪范围。
日薪岗位只展示原文，不参与图表。
未公开薪资不参与图表。
薪资数据来自岗位原文或人工补充字段。
```

显示规则建议：

- 月薪：进入图表
- 日薪：展示原文标签
- 未公开：显示“未公开”，不进入图表
- 无法解析：显示“待确认”，不进入图表

### 4. 面试报告导出入口

目标：方便答辩展示和提交材料。

建议先支持 Markdown 导出。

按钮位置：

```text
面试记录 → 查看报告 → 导出 Markdown
```

导出内容建议包括：

- 面试基本信息
- 总分
- 分维度得分
- 每题反馈
- STAR 改写建议
- 下一轮训练计划

PDF 可以作为后续拓展，不要求今天必须完成。



## 验收方式

### 场景一：普通学生用户

登录学生账号后：

- 看不到岗位审核入口。
- 首页能看到完整流程引导。
- 可以从简历管理进入岗位匹配。
- 可以从匹配结果选择岗位进入多岗对比。

### 场景二：审核员用户

登录审核员账号后：

- 能看到岗位审核入口。
- 可以筛选待审核岗位。
- 可以批量通过岗位。
- 审核后能看到更新索引提醒。

### 场景三：多岗对比

从岗位匹配页选择 3 个岗位：

- 点击“查看对比”后进入多岗对比页。
- 多岗对比页只展示选中的岗位。
- 薪资图表不显示未公开岗位为 0。
- 页面说明薪资统计口径。

### 场景四：报告导出

完成一次面试后：

- 能在面试记录中打开报告。
- 能点击“导出 Markdown”。
- 导出内容包含总分、逐题反馈、STAR 建议和训练计划。

## 结论

前端组员今天最有价值的工作，是把已经实现的功能串成用户能理解的完整流程。

最推荐优先做：

1. 首页流程引导
3. 匹配结果加入多岗对比
4. 看板和薪资图表说明
5. 面试报告 Markdown 导出
